Moving is just adding

To the computer, the hero is just a few numbers: where it is, and how fast it is going.

  • Position: where the hero is. x is east-west, z is north-south, y is up-down.
  • Velocity: how fast it moves in each direction, in cells per second.

Every frame, the game does a tiny bit of adding:

position = position + velocity × dt

And gravity is just as simple. Every frame, it pulls the up-down speed down a bit:

velocity.y = velocity.y - 22 × dt

That is all you need for a jump: set the up-speed to a big number, and gravity bends it back down into a nice curve.

Tricks that make it feel good

Real physics is not always fun. Game makers cheat a little, on purpose, so the controls feel fair:

Coyote time

Like the cartoon coyote who runs off a cliff and only falls when he looks down: for 0.12 seconds after you walk off an edge, you can still jump. Without it, you would often press jump "just too late" and fall, and it would feel unfair.

Try it in the demo: switch coyote time off and jump very late at the edge of the water.

Jump buffer

If you press jump a tiny moment before you land (up to 0.15 seconds), the game remembers it and jumps as soon as your feet touch the ground.

Speed ramp

You don't reach full speed instantly: it takes 0.25 seconds. But stopping is fast (about 0.1 seconds). Short taps stay precise, and you never slide past where you wanted to stop.

The leap

Jumping while running gives you a little push forward: just enough to get over a gap of one cell. The world builder knows this number too, and only plans jumps you can really make!

Bumping into things

Sliding along walls. Walk diagonally into a wall: you don't stop dead, you slide along it. The trick: the game moves you east-west first and checks for a wall, then north-south and checks again. If only one direction is blocked, the other one still works.

Little steps. A ledge up to 0.3 units high is walked up without jumping. Higher than that, you need to jump.

Walking downhill. Without help, you would fly off every little slope like off a ramp. So when you are on the ground, the game sticks you to the floor if it is less than 0.25 units below you.

Slopes. Walking uphill is slower. Slopes that are too steep make you slide down.

Ceilings. Jump under a bridge, and you bump your head: your upward speed is set to zero.

Fluids. Water, lava and acid are deadly. When you walk towards their edge, the game stops you. But a jump, a knockback or a fall can still carry you in. So be careful!

Think Why does the game stop you at the edge of water when walking, but not when jumping? (Because walking in by accident is annoying, but jumping is a choice!)

Hard landings

When you land, the game looks at how fast you were falling:

FALLING SPEEDWHAT HAPPENS
up to 10a normal landing
more than 10you land on your bottom and are dizzy for a moment
more than 14you tumble over as a ragdoll, and it hurts: up to 60 damage

Falling speed grows the longer you fall, so this is really about how high you fell. Try the drop buttons in the jump demo!

Falling into the cube below

Some cubes have holes, open to the depth below. Fall in, and you slide down into the cube below... but the landing costs the full 60 damage, and puts you back in the cube you fell from, at the last safe spot. No shortcuts!

The holes line up with the world: there is only a hole where the cube below really exists.

Floppy! The ragdoll

When the hero gets knocked over, the animation stops, and a ragdoll takes over: the body flops around by physics, like a puppet with cut strings. It's made of just dots and sticks. Knock it over, kick it, or grab a dot and throw it!

This is the game's ragdoll, flattened into a side view. The game's version works the same way in 3D.

How a ragdoll works

The ragdoll has 16 dots, one at each joint: pelvis, chest, neck, head, shoulders, elbows, hands, hips, knees and feet.

  1. Move every dot as if it were alone. Its speed? Where it is now, minus where it was one step ago. (This trick is called Verlet.) Add gravity.
  2. Fix the sticks. Some sticks are now too long or too short. Push both ends towards the right length.
  3. Fixing one stick breaks another a bit... so fix them all 6 times. Close enough!
  4. Floor: a dot below the floor is put back on top, and slowed down (friction).

That runs 120 times a second, more often than the picture, so it stays stable.

Getting up again

When the dots stop moving, the game checks: is the body lying face down or on its back? Then it plays the matching "get up" animation.

The tricky part: the animation was made for a body lying in one exact pose, but the ragdoll lies in a random heap. So the game smoothly morphs the ragdoll's pose into the first frames of the get-up animation, and turns the hero to match. The feet stay planted, so nothing slides.

The real code: jumping

const LEAP = 3.4;   // horizontal speed of a jump while moving

// jump with a little coyote time (just walked off a ledge) and a short input buffer
function jumping(dt, jump) {
  const p = player;
  p.coyote = p.grounded && !p.swimming ? 0.12 : p.coyote - dt;
  p.jumpBuf = jump ? 0.15 : p.jumpBuf - dt;
  if (p.jumpBuf <= 0 || !(p.coyote > 0 || p.swimming)) return;
  p.vy = p.swimming ? 4.8 : JUMP_V;
  // jumping while moving is a leap: enough speed to clear a one-cell gap
  const s = Math.hypot(p.vx, p.vz);
  if (!p.swimming && s > 0.8 && s < LEAP) { p.vx *= LEAP / s; p.vz *= LEAP / s; }
  p.grounded = p.swimming = false;
  p.coyote = p.jumpBuf = 0;
  p.jumpCount++;
}

p.coyote is a timer. On the ground it is always reset to 0.12. In the air it counts down by dt every frame.

p.jumpBuf is a timer too: pressing jump sets it to 0.15, then it counts down.

The jump only happens if both timers are still above zero. That's the whole trick: two countdowns!

In water, the same code makes you paddle up out of the water, a bit slower (4.8).

Math.hypot(vx, vz) is the speed along the ground (Pythagoras!).

The real code: one ragdoll step

substep() {
  const g = GRAV * SUB * SUB;
  for (let i = 0; i < this.p.length; i++) {
    const q = this.p[i], o = this.o[i];
    const vx = (q[0] - o[0]) * 0.998, vy = (q[1] - o[1]) * 0.998, vz = (q[2] - o[2]) * 0.998;
    o[0] = q[0]; o[1] = q[1]; o[2] = q[2];
    q[0] += vx; q[1] += vy - g; q[2] += vz;
  }
  for (let it = 0; it < ITERS; it++) {
    for (const [a, b, len] of this.sticks) this.solve(a, b, len, false);
    for (const [a, b, len] of this.apart) this.solve(a, b, len, true);
    for (let i = 0; i < this.p.length; i++) this.collide(i);
  }
}

solve(a, b, len, apartOnly) {
  const A = this.p[a], B = this.p[b];
  const dx = B[0] - A[0], dy = B[1] - A[1], dz = B[2] - A[2];
  const d = Math.hypot(dx, dy, dz) || 1e-6;
  if (apartOnly && d >= len) return;
  const k = (d - len) / d * 0.5;
  A[0] += dx * k; A[1] += dy * k; A[2] += dz * k;
  B[0] -= dx * k; B[1] -= dy * k; B[2] -= dz * k;
}

p is where each dot is, o where it was ("old"). Their difference is the speed. 0.998 loses a tiny bit each step, like air slowing it down.

solve measures a stick (d), compares it with its length (len) and moves both ends half of the difference (* 0.5) towards each other or apart.

"Apart" sticks only push, never pull: they just stop a knee from folding all the way into the hip.
