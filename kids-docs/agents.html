What is a coding agent?

Was ist ein Coding-Agent?

A coding agent is an AI helper that can work on a program with you. You tell it what you want, in normal words. It does the typing.

Ein Coding-Agent ist ein KI-Helfer, der mit dir an einem Programm arbeiten kann. Du sagst ihm in normalen Worten, was du willst. Er macht das Tippen.

Unlike a chatbot that only talks, an agent can:

Anders als ein Chatbot, der nur redet, kann ein Agent:

  • read all the files of the game,
  • alle Dateien des Spiels lesen,
  • change them,
  • sie ändern,
  • run commands: the tests, the game's tools, Blender,
  • Befehle ausführen: die Tests, die Werkzeuge des Spiels, Blender,
  • and sometimes look at screenshots and pictures.
  • und manchmal Screenshots und Bilder anschauen.

Cube Crawler was built this way: a person with ideas and taste, working with agents. About 100 saved steps in three days.

Cube Crawler wurde so gebaut: ein Mensch mit Ideen und Geschmack, zusammen mit Agenten. Ungefähr 100 gespeicherte Schritte in drei Tagen.

But remember

Aber denk dran

The agent is fast and has read a lot of code. But it was not there when the game was planned. It only knows:

Der Agent ist schnell und hat viel Code gelesen. Aber er war nicht dabei, als das Spiel geplant wurde. Er weiß nur:

  • what is written in the files,
  • was in den Dateien steht,
  • what you tell it.
  • was du ihm sagst.

It can misunderstand you. It can make mistakes, and sometimes it is very sure about something wrong. That's why you are still the boss: you decide what the game should be, and you check if it's fun.

Er kann dich missverstehen. Er kann Fehler machen, und manchmal ist er sich bei etwas Falschem sehr sicher. Darum bist du immer noch der Chef: Du entscheidest, was das Spiel sein soll, und du prüfst, ob es Spaß macht.

The building loop

Die Bauschleife

Working with an agent is a loop, a bit like the game loop:

Mit einem Agenten zu arbeiten ist eine Schleife, ein bisschen wie die Spielschleife:

  1. Ask: say what you want. One thing at a time.
  2. Fragen: Sag, was du willst. Eine Sache auf einmal.
  3. Understand: the agent reads the code. (Ask it to explain what it found!)
  4. Verstehen: Der Agent liest den Code. (Lass ihn erklären, was er gefunden hat!)
  5. Change: it edits the files.
  6. Ändern: Er bearbeitet die Dateien.
  7. Check: it runs the tests: little programs that check the game still works.
  8. Prüfen: Er lässt die Tests laufen: kleine Programme, die prüfen, dass das Spiel noch funktioniert.
  9. Play: you play the game and look. Does it feel right? Is it fun?
  10. Spielen: Du spielst das Spiel und schaust hin. Fühlt es sich richtig an? Macht es Spaß?
  11. Keep or undo: happy? Save it (a "commit"). Not happy? Say what's wrong, or undo it.
  12. Behalten oder zurück: Zufrieden? Speichern (ein "Commit"). Nicht zufrieden? Sag, was nicht stimmt, oder mach es rückgängig.

Then the next idea. Small loops are better than big ones: if something breaks, you know which step broke it.

Dann die nächste Idee. Kleine Schleifen sind besser als große: Wenn etwas kaputtgeht, weißt du, welcher Schritt es war.

What makes a good prompt

Was einen guten Prompt ausmacht

Not so good

Nicht so gut

"make the game better"

"mach das Spiel besser"

Better how? The agent has to guess, and it will guess something you didn't want.

Besser wie? Der Agent muss raten, und er rät etwas, das du nicht wolltest.

"spiders are broken"

"Spinnen sind kaputt"

Broken how? Where? When?

Kaputt wie? Wo? Wann?

"add multiplayer, a shop, crafting and a dragon"

"bau Mehrspieler, einen Laden, Handwerk und einen Drachen ein"

Four huge things at once. If it goes wrong, where do you even start?

Vier riesige Dinge auf einmal. Wenn es schiefgeht, wo fängst du überhaupt an?

Good

Gut

  • What you want: "Make spiders notice me from further away, about 5 cells instead of 3."
  • Was du willst: "Lass Spinnen mich von weiter weg bemerken, etwa 5 Zellen statt 3."
  • What happens now: "Right now they only notice me when I'm almost next to them." The agent finds the code by itself.
  • Was jetzt passiert: "Gerade bemerken sie mich erst, wenn ich fast neben ihnen stehe." Den Code findet der Agent selbst.
  • How to check: "Run the tests."
  • Wie man prüft: "Lass die Tests laufen."
  • Limits: "Only spiders, don't change the other monsters."
  • Grenzen: "Nur Spinnen, ändere die anderen Monster nicht."
  • Show me: "Tell me what you changed."
  • Zeig es mir: "Sag mir, was du geändert hast."

For bugs: say what you did, what happened and what you expected. Give the seed: "seed 123, depth 4, I jumped from the bridge into lava and didn't die."

Bei Fehlern: Sag, was du gemacht hast, was passiert ist und was du erwartet hast. Gib den Seed an: "Seed 123, Tiefe 4, ich bin von der Brücke in die Lava gesprungen und nicht gestorben."

Probier es: Bau einen Prompt

Wähl eine Idee (oder schreib deine eigene) und hak die guten Gewohnheiten an. Dann kopier den Prompt und probier ihn mit einem Agenten aus!

Tests: inspectors that never get tired

Tests: Prüfer, die nie müde werden

A test is a small program that uses the game's code and checks one thing. For example:

Ein Test ist ein kleines Programm, das den Code des Spiels benutzt und eine Sache prüft. Zum Beispiel:

test('running ramps up over RUN_RAMP, passing walking pace early, so taps stay precise', () => {
  stand();
  const walk = until(WALK_SPEED, 1, 0, true);
  assert.ok(walk.t < RUN_RAMP * 0.75, 'walking pace after about 70% of the ramp: ' + walk.t);
  stand();
  const run = until(RUN_SPEED, 1, 0, true);
  assert.ok(Math.abs(run.t - RUN_RAMP) <= DT, 'full run after RUN_RAMP: ' + run.t);
});

Type npm test, and all of them run. Green: all good. Red: something you changed broke something, maybe something you didn't even think about.

Tipp npm test, und alle laufen. Grün: alles gut. Rot: Etwas, das du geändert hast, hat etwas kaputtgemacht, vielleicht etwas, an das du gar nicht gedacht hast.

A true story

Eine wahre Geschichte

The hero used to run at 4.1 cells per second. It felt too fast, so the run was slowed down to 2.8.

Der Held rannte früher mit 4,1 Zellen pro Sekunde. Das fühlte sich zu schnell an, also wurde das Rennen auf 2,8 verlangsamt.

And then a test failed! It checked that, when you start running, you reach walking speed after about half of the speed-up time. With the slower run, that now took 70%.

Und dann schlug ein Test fehl! Er prüfte, dass man beim Losrennen nach etwa der Hälfte der Anlaufzeit Gehtempo erreicht. Mit dem langsameren Rennen dauerte das jetzt 70%.

Was that bad? No, it was fine, so the test was updated to say 70%, and the notes in docs/combat.md too. Three files, one small saved step.

War das schlimm? Nein, es war in Ordnung, also wurde der Test auf 70% geändert, und die Notizen in docs/combat.md auch. Drei Dateien, ein kleiner gespeicherter Schritt.

Lesson: a failing test is not always a bug. It's a question: "did you mean to change this?"

Lehre: Ein fehlschlagender Test ist nicht immer ein Fehler. Er ist eine Frage: "Wolltest du das ändern?"

Save points: git

Speicherpunkte: git

Games have save points. Code has git. Every time something works, you save a commit: a snapshot of all files, with a message saying what changed.

Spiele haben Speicherpunkte. Code hat git. Jedes Mal, wenn etwas funktioniert, speicherst du einen Commit: einen Schnappschuss aller Dateien, mit einer Nachricht, was sich geändert hat.

If the agent's next change goes wrong, you can always go back to the last commit. That makes it safe to try wild ideas!

Wenn die nächste Änderung des Agenten schiefgeht, kannst du immer zum letzten Commit zurück. Darum ist es sicher, wilde Ideen auszuprobieren!

Useful things to ask:

Nützliche Fragen:

  • "Show me what changed since the last commit." (git diff)
  • "Zeig mir, was sich seit dem letzten Commit geändert hat." (git diff)
  • "Undo all changes since the last commit."
  • "Mach alle Änderungen seit dem letzten Commit rückgängig."
  • "Commit this with a good message."
  • "Speicher das als Commit mit einer guten Nachricht."

Some real commit messages from this game:

Ein paar echte Commit-Nachrichten aus diesem Spiel:

feat(loot): add generated weapon drops with rarity glows and floor panel
feat(player): get up from ragdolls with authored clips
fix(player): keep feet planted while getting up
feat(audio): give every theme its own song
fix(player): slow the run and match its cycle and footsteps
feat(dev): spawn any enemy kind from the dev panel

"feat" means a new feature, "fix" a repair. The word in brackets is the part of the game. Short, clear, one thing each.

"feat" heißt neue Funktion, "fix" eine Reparatur. Das Wort in Klammern ist der Teil des Spiels. Kurz, klar, eine Sache pro Nachricht.

When it goes wrong

Wenn es schiefgeht

  • Describe what you see, exactly. "The spider walks through the wall on depth 3, seed 55, near the stairs." Screenshots help a lot.
  • Beschreib genau, was du siehst. "Die Spinne läuft in Tiefe 3, Seed 55, bei der Treppe durch die Wand." Screenshots helfen sehr.
  • Ask for the cause first. "Find out why this happens, but don't fix it yet." Then decide together.
  • Frag zuerst nach der Ursache. "Finde heraus, warum das passiert, aber repariere es noch nicht." Dann entscheidet ihr zusammen.
  • Ask "why?" If you don't understand a change, ask. A good change can be explained simply.
  • Frag "warum?" Wenn du eine Änderung nicht verstehst, frag nach. Eine gute Änderung lässt sich einfach erklären.
  • Make it smaller. If a big change keeps failing, undo it and do just the first part.
  • Mach es kleiner. Wenn eine große Änderung immer wieder scheitert, mach sie rückgängig und mach nur den ersten Teil.
  • Start fresh. If a conversation gets confused, start a new one with a clearer prompt. Mention what you learned.
  • Fang neu an. Wenn ein Gespräch durcheinander gerät, fang ein neues mit einem klareren Prompt an. Erwähne, was du gelernt hast.
  • Write it down. When you figure something out, ask the agent to add it to the docs. The next agent (or you, next month) will thank you.
  • Schreib es auf. Wenn du etwas herausgefunden hast, bitte den Agenten, es in die Doku zu schreiben. Der nächste Agent (oder du, nächsten Monat) wird dir danken.
Remember You don't need to understand every line of code to build a game this way. But the more you understand, the better your prompts get, and the better your game gets. That's what this guide is for!
Denk dran Du musst nicht jede Codezeile verstehen, um so ein Spiel zu bauen. Aber je mehr du verstehst, desto besser werden deine Prompts, und desto besser wird dein Spiel. Dafür ist dieser Führer da!

A real change, from idea to commit

Eine echte Änderung, von der Idee zum Commit

fix(player): slow the run and match its cycle and footsteps

 docs/combat.md         | 4 ++--
 src/core/constants.js  | 6 +++---
 tests/movement.test.js | 2 +-

--- a/src/core/constants.js
+++ b/src/core/constants.js
-export const WALK_SPEED = 1.9, RUN_SPEED = 4.1, SWIM_SPEED = 0.9;
+export const WALK_SPEED = 1.9, RUN_SPEED = 2.8, SWIM_SPEED = 0.9;
-export const WALK_ANIM = 1.4, RUN_ANIM = 3.2;
+export const WALK_ANIM = 1.4, RUN_ANIM = 2.8;   // the run: its authored stride, no stretch

--- a/tests/movement.test.js
+++ b/tests/movement.test.js
-  assert.ok(walk.t < RUN_RAMP * 0.55, 'walking pace after about half the ramp: ' + walk.t);
+  assert.ok(walk.t < RUN_RAMP * 0.75, 'walking pace after about 70% of the ramp: ' + walk.t);

This is how a change looks to git. Lines with - were removed, lines with + added.

So sieht eine Änderung für git aus. Zeilen mit - wurden entfernt, Zeilen mit + hinzugefügt.

The idea: "the run is too fast, and the legs don't match the speed". The change:

Die Idee: "Das Rennen ist zu schnell, und die Beine passen nicht zum Tempo." Die Änderung:

  1. the rule: RUN_SPEED from 4.1 to 2.8,
  2. die Regel: RUN_SPEED von 4,1 auf 2,8,
  3. the look: the run animation now plays at the same pace (RUN_ANIM), so the feet don't slide,
  4. das Aussehen: Die Rennanimation spielt jetzt im selben Tempo (RUN_ANIM), damit die Füße nicht rutschen,
  5. the check: the test, updated on purpose,
  6. die Prüfung: der Test, absichtlich angepasst,
  7. the notes: docs/combat.md.
  8. die Notizen: docs/combat.md.

Rule, look, check, notes. A good change usually touches all four.

Regel, Aussehen, Prüfung, Notizen. Eine gute Änderung berührt meistens alle vier.
